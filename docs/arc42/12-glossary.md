# 12. Glossary

Terms used consistently across this documentation. Alphabetically ordered.
Candidate terms from the ideation topic are marked as such and are not part of
the implemented architecture. Terms promoted from the `secure-token-keys`
ideation topic on 2026-10-17 are confirmed vocabulary; they do not prove that
token behavior is implemented.

| Term | Definition |
|---|---|
| Agent version floor | The declared minimum version of a coding agent that a device's configuration asserts at evaluation time (today `18.10` for Oh My Pi (omp) and `2.0.28` for OpenCode, on `thiniel` and `J6G6Y9JK7L`). A floor, not a schedule: taking a newer agent is a deliberate owner action (refreshing the agent's source pin or its package), so the floor fails a regression rather than tracking upstream releases. |
| Assertion (`config.assertions`) | An evaluation-time check declared by a module (`tests/assertions/*-invariants.nix`). The host configuration fails to evaluate if it does not hold. |
| Backup security key | The separately stored security key registered as its own credential, never a copy of the daily security key. In the `secure-token-keys` topic, the Solo 2. Anti-terms: backup token (ambiguous with an OAuth token), duplicate key. |
| Binding tag | The single `@check:<name>`, `@host:<name>`, or `@deploy:<name>` tag a scenario carries to name the native target that proves it (`docs/GIVN-VERIFICATION.md`). |
| Check (flake `checks`) | A derivation exposed by the flake: `unit-helpers`, `lint-deadnix`, `lint-statix`, `lint-nixfmt`, `private-data-defaults`, `private-data-hygiene`, `flake-output-contract`, `unit-agent-secret-guard` on all systems; `integration-vm-minimal-ssh`, `integration-adlerkopf`, `integration-ssh-identity-selection`, `integration-private-data-separation`, `integration-agent-tooling`, `integration-managed-file-displacement`, `integration-github-fetch-credential`, `integration-rust-toolchain` on Linux. `private-data-defaults`, `private-data-hygiene` and `integration-private-data-separation` are added by the change `private-data-remediation`; `unit-agent-secret-guard` and `integration-agent-tooling` by the change `current-omp-release`; `flake-output-contract` by the change `quiet-configuration-evaluation`; `integration-managed-file-displacement` by the change `managed-file-displacement`; `integration-github-fetch-credential` by the change `github-fetch-credential`; `integration-rust-toolchain` by the change `rust-build-toolchain`. |
| Coding agent | A tool installed on a personal device that performs code and shell work on the device owner's behalf under that device's configuration. Not an application: an application serves the operator's task through its own interface and data, while a coding agent acts with the operator's device permissions — which is why a device constrains it (`Secret-access guard`). On `thiniel` and `J6G6Y9JK7L` the coding agents are Oh My Pi (omp) and OpenCode. |
| Colmena hive | The `colmenaHive` flake output intended for coordinated fleet deployment. Declared with **zero** nodes; the change `quiet-configuration-evaluation` withdraws the output (and its flake input) because the checker reports every output it does not recognise, and registers it again with the first server provisioned for fleet deployment. The Colmena CLI and the operator's fleet aliases stay installed. |
| Connection entry | The SSH client configuration entry (host block) a device renders for one identity, naming that identity's file. |
| Daily security key | The security key the owner carries for routine authentication, distinct from the separately stored backup security key. In the `secure-token-keys` topic, the Swissbit iShield Key. Anti-term: primary token. |
| Declared | Evidence label: the Nix source states it and it is rendered into a configuration. It is not proof of live behaviour. |
| disko | Declarative disk partitioning/formatting module used for the hosts that are installed from the flake. |
| Displaced file | A managed file that existed as a different regular file when the configuration was applied: the activation renames it to the first free `<name>.<n>` beside the rendered file (`lib/helpers.nix` `mkManagedFileDisplacement`), so it is kept and the activation completes. Written by the change `managed-file-displacement`. |
| Documentation-range placeholder | A host network default drawn from a range reserved for documentation (RFC 5737 `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) or a generic RFC 1918 range, so the public default identifies no real network. |
| Enrolled credential | One security key's token-held personal identity, represented by its public identity and non-resident key handle file; not a remote authorization and not a copy of another key's credential. Anti-term: copied key. |
| Enrollment | The act of creating a personal-identity credential on a specific security key and recording its non-resident key handle in the identity declaration. Contrast: remote authorization, which grants access at a remote. Anti-term: registration (used for both acts). |
| Feature module | A Home Manager module under `home/dan/features/<category>/` that renders one concern (tool, service, desktop component) from host declarations, platform conditionals, and declared secrets. |
| File-backed personal identity | The personal identity backed by a private key file on the device, retained as the first-stage fallback in the `secure-token-keys` topic; not a token-held personal identity and not theft resistance. Anti-term: file key (names the file, not the identity). |
| Flake | The repository's single Nix entry point (`flake.nix` + `flake.lock`) that declares all host configurations and outputs. |
| Generation | One built and activatable system or home profile revision. Rollback is selection of an older generation. |
| GitHub fetch credential | The credential a device's package manager presents when it downloads a source from the GitHub host (`access-tokens = github.com=<value>`). A machine that develops or builds this configuration declares it as secret material (`github/access-token`) and sops-nix renders the fragment at mode `0400`, owned by the device owner: on the Linux build machine by system activation into `/run/secrets/rendered/`, on the work MacBook by the owner's home-manager session under `~/.config/sops-nix/`. The machine's nix configuration *includes* the fragment — never a configuration literal, a store path, or a process environment variable — and both the owner's clients and root's read it (root by privilege). Distinct from `Identity file` (which authenticates a Git transport for a person) and from `Operational value` (which is kept out of the repository rather than encrypted). Introduced by the change `github-fetch-credential`. |
| Guard | `scripts/private_data_hygiene.py`: the rule that refuses a revision recording an operational value, a per-host private-value file, or an unencrypted secret. Run as the `private-data-hygiene` flake check, as a pre-commit hook, and in CI. |
| Home profile | The Home Manager configuration of one host user (`home/dan/<host>.nix`). |
| Host | One declared machine configuration under `hosts/<host>/` mapped in the flake to a `nixosConfiguration` or `darwinConfiguration`. |
| Identity declaration | A host's statement of which identity material that device holds (`myHome.ssh`), from which the connection entries and the workspace identity configuration are rendered. |
| Identity file | The private key file a device presents to authenticate to a remote Git host. |
| Identity material | The private keys a device holds for the identities it uses; a device declares it, and a connection entry is rendered only where the device declares the material for that identity. |
| Impermanence | The model in which a stateful host's root filesystem is reset on every boot and only explicitly declared paths survive. |
| Intended | Evidence label: an accepted requirement or confirmed decision that is **not** implemented in the working tree. |
| Key handle | The on-disk reference that lets a device ask a specific security key to authenticate; not a usable private key and not a public identity. In the `secure-token-keys` first stage it is **non-resident**: it exists only in the handle file on the device, not in the token. Anti-term: key file. |
| Managed file | A file the home profile renders into the user's home (a `home.file` entry, or a file a program module renders such as the browser's profile registry); Home Manager links it to the store and owns that target. A program the file configures may write the target itself. |
| `mkPkgsUnstable` | Helper in `lib/helpers.nix` that builds the unstable package set (`pkgs-unstable`) injected into host configurations. |
| Model server (MCP server) | An external service the coding agent consults over the Model Context Protocol: `context7` (documentation lookup, HTTP) and `kagi-search` (web search, stdio). Declared per device: Oh My Pi (omp) declares them in `~/.omp/agent/mcp.json`, where each key is read from the device's secret store at connect time through the agent's `!command` indirection, so a missing key drops that entry instead of failing the agent; OpenCode declares its own two servers (`context7` remote, `kagi-search` local) in `~/.config/opencode/opencode.json`, reading each key from the environment. |
| `myHome.*` | The reusable Home Manager option namespace declared under `modules/home-manager/*` and filled by a host profile (`myHome.ssh`, `myHome.persistence`). |
| `mySystem.*` | The reusable NixOS option namespace declared under `modules/nixos/*` and filled by a host module (`mySystem.persistence`). |
| `@e2e` | Tag marking a scenario that must bind to a real boot (VM) or a host confirmed on hardware, never to a plain unit/lint check. |
| netcup SCP | The netcup Server Control Panel, whose external firewall is managed account-side by `scripts/netcup_firewall.py`. |
| Operational value | A host's real network identity — address, gateway, hardware address, resolver, port — that identifies or maps the operator's infrastructure and must not appear in the public repository or its history. |
| Option module | A pair `modules/<kind>/<concern>/options.nix` + `default.nix` that declares a typed surface and renders its behaviour. |
| Per-host private-value file | A host's real values in a local file (`hosts/<host>/private.nix`). The repository forbids recording one, and the `git+file://` source rule makes an untracked one unusable, so it is not a mechanism — the `private` flake input is. |
| Personal identity | The device owner's own identity on a device: its private key and the connection and workspace surfaces derived from that key. |
| Persistence | The declared set of paths bound from the persistent volume to survive a root wipe. Split into a system layer (`mySystem.persistence`) and a user layer (`myHome.persistence`). |
| Private source | The local private flake (`~/dev/PRIVATE/nix-private`) that supplies a host's real values through the overridable `private` input. |
| Private workspace | The workspace directory whose Git operations use the device's personal identity, selected by the host's include rule. |
| Public identity | The public half of an enrolled token-held personal identity, presented to a remote host for authorization; it grants nothing by itself. Anti-term: public key (the encoding, not the authorization relationship). |
| RED/GREEN/REFACTOR | The mandatory per-change loop: the bound target must be observed failing before the configuration change and passing after it. |
| Remote authorization | The grant at a remote host that admits a specific public identity; separate from local enrollment and not an account recovery policy. Anti-term: registration. |
| Remote host | An external system that authenticates the owner's public identity, such as GitHub or a server; not the personal device and not the security key. |
| Rust build toolchain | The device's one default set of tools for building and measuring Rust projects: the compiler (`rustc`), package manager (`cargo`), formatter (`rustfmt`), lint driver (`clippy`) and the `llvm-tools-preview` coverage tools (`llvm-profdata`, `llvm-cov`), all from one released Rust distribution (the pinned `rust-overlay` on `thiniel`), plus `cargo-llvm-cov`, a C linker (`gcc`) and `pkg-config`, and a Cargo home declared persistent. The compiler and the tools that read its coverage profiles must come from the same release; the channel packages them from different builds. Distinct from a project's own toolchain pin, which the device does not follow. On `thiniel` the `development/rust` feature module provides it (asserted by `thiniel-hm-invariants`; built, formatted, linted and measured by the check `integration-rust-toolchain`). |
| Secret-access guard | The coding agent's pre-execution hook (`.omp/hooks/pre/secret-access-guard.js`) that refuses decryption commands (`sops`, `age -d`/`--decrypt`, `ssh-to-age`) and reads of decrypted material (`/run/secrets/*`, a `sops/age/` path, `/var/lib/sops-nix/`) in every approval mode. Installed on a device as a regular file in the agent's user directory. Distinct from `Guard`, which is the repository's rule over recorded content. |
| Security key | A FIDO2/CTAP2.1 hardware authenticator the owner holds that performs authentication without exporting its private key. Anti-terms: token (ambiguous with OAuth access/refresh tokens), USB key (too broad). |
| SOPS / age | The secret scheme: SOPS-encrypted YAML files whose recipients are age keys, mapped per host file in `.sops.yaml`. |
| Stub (private-input stub) | `private-stub/flake.nix`: the public default for the `private` input. It supplies no values and asserts the host network defaults are documentation-range placeholders, so a clean clone evaluates without private access. |
| stylix | The theming module supplying the system-wide palette (One Light) with per-target opt-in. |
| Success guarantee (ideation) | The standalone outcome a change seed promises; a seed is input to a future proposal, not an implemented capability. |
| Superseded default | A setting whose release default changed after a profile's state version was fixed (the state version is set at install time and never changed), so the release keeps the older value for that profile and reports a migration warning until the profile states the value explicitly — either the older one or the release's current one. The change `quiet-configuration-evaluation` resolves the two such settings of the personal laptop's home profile (the window-manager configuration format, kept; the browser profile location, moved to the release's current value). |
| thiniel / adlerkopf / cupix001 / nixos-vm-minimal / J6G6Y9JK7L | The five declared host identities: Linux laptop, home server, netcup VPS (planned edge ingress gateway, still a skeleton), minimal test VM, and work macOS workstation. |
| Token-held personal identity | A personal identity whose private key is held and used by a security key while the device keeps only a non-resident key handle file; a specialization of [[Personal identity]], not a file-backed personal identity. Anti-term: hardware key identity. |
| Verified | Evidence label: a native target reproduced the behaviour (host evaluation, assertion, unit test, or booted QEMU VM). |
| Work identity | An employer or client identity, with its own key and connection entry, declared only on a device that holds that identity's material. |

## Candidate terms (not promoted)

The ideation topic "Growing personal and family infrastructure" records seven
**candidate** domain terms that remain topic-local and unpromoted; the durable
glossary above deliberately does not include them. Nothing in the working tree
confirms them as implemented concepts. The topic record itself is the authority:
[`givn/ideation/infrastructure-growth/domain-terms.md`](../../givn/ideation/infrastructure-growth/domain-terms.md).
